# CLAUDE.md — OmniStack Root Architecture Specification

## 1. System Overview & Core Philosophy
OmniStack is a production-ready, full-stack boilerplate for Web (Nuxt 4) and Mobile (Flutter), powered by a Serverless Hono API on AWS Lambda.

### Core Architectural Principle: **$0 Idle Cost**
- NO resource or service used in this project may incur a fixed monthly charge at zero traffic.
- Infrastructure MUST rely strictly on consumption-based pricing (AWS Lambda, S3, Neon Serverless Postgres, Firebase Auth, Stripe).

---

## 2. Monorepo Structure & Package Boundaries
This repository is managed as a monorepo workspace.

```
/
├── apps/
│   ├── backend/             # Hono API (AWS Lambda via SST v3 Ion)
│   └── frontend/            # Nuxt 4 Web Application (Tailwind CSS, Nuxt UI v3)
├── packages/
│   └── core/                # Shared DB Schemas, Drizzle config, Shared Types, & Scripts
│       └── src/
│           └── db/
│               └── schema.ts # SINGLE SOURCE OF TRUTH FOR DATABASE SCHEMAS
├── sst.config.ts            # SST v3 (Ion) Infrastructure definition (Root)
└── CLAUDE.md                # This specification
```

## 4. User ID & Database Mapping Standard
- **Primary Key Rule:** The `users.id` in Neon Postgres (`packages/core/src/db/schema.ts`) MUST match the exact string value of the Firebase Authentication `UID` (`firebase_uid`).
- **User Creation Flow:** When a user registers via Firebase Auth (Web or Mobile), the client sends the Firebase ID Token to Hono (`POST /api/user/sync`), which upserts the user row in Neon DB using the Firebase `UID` as `id`.

---

## 5. API Design & Hono RPC Standard

### 5.1 Response Structure
ALL Hono endpoints MUST return JSON conforming to this TypeScript interface:
```typescript
type ApiResponse<T> = 
  | { success: true; data: T; error: null }
  | { success: false; data: null; error: { code: string; message: string } };
```

### 5.2 Hono RPC End-to-End Type Safety
- The Hono API in `apps/backend` MUST export the route type (`export type AppType = typeof routes`).
- The Nuxt frontend (`apps/frontend`) MUST instantiate `$fetch` wrapper using `hc<AppType>()` from `hono/client`.
- DO NOT manually write TypeScript interfaces for API payloads on the frontend if they can be inferred via Hono RPC or exported from `packages/core`.

---

## 6. Authentication & Authorization Middleware Rules
- Every protected route in Hono MUST pass through an `requireAuth` middleware.
- The middleware extracts the `Authorization: Bearer <token>` header, verifies it using `firebase-admin` (or cryptographically via Firebase public JWT keys), and sets the decoded user context via `c.set("userId", ...)` / `c.set("email", ...)` (typed through the shared `Env` variables type), readable downstream as `c.get("userId")` / `c.get("email")`.
- If verification fails, return HTTP `401 Unauthorized` immediately with standard error JSON.

## 7. Stripe & Webhook Execution Flow
- **No Custom Credit Card Forms:** Frontend MUST redirect users to Stripe Pre-built Checkout.
- **Webhook Handling (synchronous, in-Lambda):**
  1. Stripe POSTs webhooks to `apps/backend` endpoint `/api/stripe/webhook`.
  2. Hono reads the raw request body and verifies the Stripe signature (`stripe.webhooks.constructEvent`) against `STRIPE_WEBHOOK_SECRET` before trusting the payload. An invalid/missing signature returns `400` immediately.
  3. On a valid signature, Hono processes the event inline, in the same request — e.g. upserting rows in `subscriptions`/`orders` in Neon DB — wrapped in `try/catch` with structured error logging.
  4. Hono returns HTTP `200 OK` to Stripe once processing completes so Stripe does not retry; a thrown/caught error returns a non-2xx status so Stripe retries the delivery.
  - **There is no queue/worker decoupling** (no SQS, no async fan-out). The webhook handler runs synchronously on the Lambda request path, so DB writes and any Stripe API calls it makes (e.g. `stripe.subscriptions.retrieve`) must stay fast, idempotent (use `onConflictDoUpdate` keyed on the Stripe id), and defensive, since Stripe enforces a response timeout and will retry on failure or timeout.

## 8. AI Code Generation Rules for Claude
1. **Never break Monorepo Imports:** Cross-package imports must use workspace aliases (e.g., `import type { User } from "@omnistack/core/db"`).
2. **Never change Schema Location:** All Drizzle tables MUST be modified inside `packages/core/src/db/schema.ts`.
3. **Keep Client Code Pure:** Do NOT write AWS SDK or Direct DB calls in `apps/frontend`. Everything goes through the Hono API.
4. **Error Handling:** Always wrap async database or third-party SDK calls in `try/catch` blocks and log structured errors before throwing/returning.
