# OmniStack

An opinionated, full-stack SaaS boilerplate for indie hackers and cloud engineers,
built around a strict **zero idle cost** constraint: the whole architecture scales
to zero when unused, while staying type-safe and deployable via infrastructure as
code.

## Stack

- **Infrastructure:** [SST v3 Ion](https://sst.dev/) (`sst.config.ts`), deploying to AWS.
- **Backend:** [Hono](https://hono.dev/) running on an AWS Lambda Function URL.
- **Auth:** Firebase Auth (Client SDK on the frontend, Firebase Admin token
  verification on the backend).
- **Database:** Neon serverless PostgreSQL with [Drizzle ORM](https://orm.drizzle.team/).
- **Storage:** AWS S3, via presigned upload URLs generated by the Hono API (used
  for profile avatars).
- **Billing:** Stripe Hosted Checkout + Customer Portal, with a synchronous,
  signature-verified webhook handler (no queue/worker decoupling).
- **Frontend:** Nuxt 4 + Vue 3 + Tailwind CSS + Nuxt UI v3 (dark/light mode).
- **CI/CD:** GitHub Actions (`.github/workflows/deploy.yml`) builds and deploys
  on every push to `main`.

## Workspace layout

This is a `pnpm` workspace with three packages:

```
apps/backend    Hono API (AWS Lambda), see apps/backend/README.md
apps/frontend   Nuxt web app, see apps/frontend/README.md
packages/core   Shared Drizzle schema/types, see packages/core/README.md
```

## Prerequisites

- Node.js and [pnpm](https://pnpm.io/).
- An AWS account configured for SST deployment.
- A [Neon](https://neon.tech/) PostgreSQL database.
- A [Firebase](https://firebase.google.com/) project with Email/Password and
  Google sign-in enabled, plus a service account for the backend.
- A [Stripe](https://stripe.com/) account with a recurring "Pro" Price created
  (Checkout and the Customer Portal are used as pre-built, hosted flows —
  no custom card forms).

## Setup

1. Install dependencies:

   ```bash
   pnpm install
   ```

2. Copy the environment template and fill in real values:

   ```bash
   cp .env.example .env
   ```

   Required variables (see `.env.example` for details):

   - `DATABASE_URL` — Neon Postgres connection string.
   - `FIREBASE_SERVICE_ACCOUNT` — Firebase Admin service account JSON, minified
     to a single line (backend only, never exposed to the browser).
   - `FIREBASE_API_KEY`, `FIREBASE_AUTH_DOMAIN`, `FIREBASE_PROJECT_ID` — Firebase
     Web app config (used by the frontend Firebase Client SDK).
   - `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` — backend-only Stripe keys for
     Checkout/Portal/webhook verification.
   - `STRIPE_PRICE_ID_PRO` — the Stripe Price id for the Pro plan; also exposed
     to the frontend (via `sst.config.ts`) so the pricing table and dashboard
     billing button know which Price to check out.

   `scripts/setup-stripe.ts` (`pnpm setup:stripe`) can register the Stripe
   webhook endpoint for you and append `STRIPE_WEBHOOK_SECRET` to `.env`
   automatically, but it's a minimal helper (no product/price creation) — you
   still need to create the Pro Price in the Stripe Dashboard yourself and set
   `STRIPE_PRICE_ID_PRO`.

3. Apply database migrations:

   ```bash
   pnpm db:push
   ```

## Development

Start everything from the repository root:

```bash
pnpm dev
```

This runs `sst dev` (the backend Lambda + Nuxt frontend, with environment
variables and resource bindings from `sst.config.ts`) together with a Stripe
CLI webhook tunnel (`stripe listen`), so Checkout/Portal events reach your
local backend during development.

## Database

Schema lives in `packages/core/src/db/schema.ts` (`users`, `subscriptions`,
`orders`). After changing it:

```bash
pnpm db:generate   # generate a new Drizzle migration
pnpm db:push        # apply migrations to DATABASE_URL via `sst shell`
```

## Deployment

Infrastructure is defined in `sst.config.ts` and deploys:

- `ProfileImages` — a public `sst.aws.Bucket` for user avatar uploads.
- `Api` — the Hono backend as an `sst.aws.Function` with a public Function URL,
  linked to `ProfileImages` and configured with the Neon/Firebase/Stripe
  environment variables.
- `Web` — the Nuxt frontend as an `sst.aws.Nuxt` app, wired to the backend's
  Function URL, public Firebase config, and the Stripe Pro Price id.

**Automated:** pushing to `main` triggers `.github/workflows/deploy.yml`, which
builds the monorepo and then runs `sst deploy --stage production`. It needs
these repository secrets configured first: `AWS_ACCESS_KEY_ID`,
`AWS_SECRET_ACCESS_KEY`, `AWS_REGION`, `DATABASE_URL`,
`FIREBASE_SERVICE_ACCOUNT`, `FIREBASE_API_KEY`, `FIREBASE_AUTH_DOMAIN`,
`FIREBASE_PROJECT_ID`, `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`,
`STRIPE_PRICE_ID_PRO`.

**Manual:** you can also deploy directly with the SST CLI (see the
[SST docs](https://sst.dev/docs/) for stage and AWS credential setup):

```bash
pnpm sst deploy --stage production
```

## Current status

Implemented: Firebase authentication (email/password + Google) with a
`requireAuth` middleware; `POST /api/user/sync` and `GET`/`PATCH
/api/user/profile`; S3 presigned avatar uploads; Stripe Checkout, Customer
Portal, and a synchronous signature-verified webhook that updates
`subscriptions`/`orders`; a best-effort in-memory rate limiter on all backend
routes; a public marketing landing page (`/`) with a $0-idle-cost calculator,
pricing table, and FAQ; and an authenticated dashboard (`/dashboard`) with
profile management, avatar upload, and a subscription/billing card. CI/CD is
configured via GitHub Actions.

Not yet implemented: Pro-only route gating (deliberately deferred, see
`specs/web-mvp-completion/feature-spec.md`), SQS/background workers,
transactional email, and a mobile app.

Detailed specs for the most recent feature work live under `specs/` (one
subdirectory per feature, e.g. `specs/web-mvp-completion/`).

## Testing and linting

No automated test suite or linter is configured yet. Validate changes using
each app's build (for example `pnpm --filter @omnistack/frontend build`) until
tests are added.
